# API design

Inspect existing API conventions and consumers before proposing a contract. Define resource or operation semantics, authentication and authorization, input validation, success and error shapes, pagination and filtering where relevant, idempotency for retries, and compatibility with existing clients. Use examples for the critical request and response paths.

Document decisions and unresolved questions. Avoid adding versioning, abstractions, or fields without a concrete use. When implementing, keep the contract, schema or documentation, tests, and runtime behavior aligned.
